# Кейс №1: Race condition

## Проблема

Два клиента одновременно обновляют одну задачу.<br>

Без механизма контроля:
- оба запроса проходят успешно
- последний запрос перезаписывает предыдущий
- изменения одного клиента **теряются**

## Альтернативы решения

### 1. Last write wins
    - 👍 просто
    - ❌ теряются данные

### 2. Pessimistic lock (`SELECT ... FOR UPDATE`)
    - 👍 исключает конфликты
    - ❌ блокирует строки, хуже под нагрузкой

### 3. Optimistic lock (version) ✅ выбран
    - 👍 не блокирует строки
    - 👍 хорошо масштабируется
    - конфликт → 409 Conflict
