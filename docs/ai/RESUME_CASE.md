# Формулировка AI-кейса для резюме

## Короткий пункт

Расширил TaskGraph AI-аналитиком backend-инцидентов: собрал workflow на
LangGraph с allowlist-инструментами, pgvector RAG и локальной LLM через
OpenAI-compatible API. Отчёт формируется только из проверенных артефактов с
SHA-256 и проходит проверку ссылок и числовых значений; на фиксированном наборе
из 20 офлайн-кейсов достигнуты 100% выбора инструментов, завершения и grounding.

## Расширенный вариант

Чтобы анализ производительности и конкурентности не зависел от свободного
текста LLM, разделил выбор инструментов и формирование результата. Модель
выбирает один из четырёх read-only инструментов, а LangGraph собирает отчёт из
версионированных evidence-артефактов и отклоняет неподтверждённые утверждения.
Добавил pgvector RAG по документации, MCP stdio-интерфейс, Prometheus-метрики и
версионированное Kafka-событие. Проверил три сценария — Seq Scan, lost update и
connection pool exhaustion — и добавил в CI 20 детерминированных офлайн-eval.

## Что нужно уметь защитить на собеседовании

- почему локальная LLM выбирает инструменты, но не генерирует итоговый JSON;
- чем grounding по evidence отличается от обычного промпта;
- как checksum, JSON Pointer и `evidence_id` предотвращают подмену фактов;
- зачем RAG хранится отдельно от измерений demo-run;
- почему CI использует StubLLMProvider и фиксированный eval-набор;
- какие данные намеренно не попадают в Kafka и Prometheus;
- почему hash embedding — воспроизводимый baseline, а не production-модель.
